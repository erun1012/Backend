# GONER 백엔드 작업 목록 (대 · 중 · 소)

> 기준: 팀 작업 분담표 + 발표자료(F1~F14).
> 스택: Firebase (Auth · Firestore · RTDB · Storage · FCM) + Cloud Run functions (Java 17)
> 크기 표기: **L** = 며칠 / **M** = 1~2일 / **S** = 반나절 이내

---

| 중 | 소 | 크기 |
|---|---|---|
| 1-1. Firebase 프로젝트 세팅 | 프로젝트 생성, Android 앱 등록(SHA-1), google-services.json 전달 | S |

## 추천 진행 순서

1. **1주차**: 대1 (스키마·규칙) → 대2 (로그인·유저) — 프론트가 바로 붙을 수 있어야 함
2. **2주차**: 대3 (친구) → 대4 (약속)
3. **3주차**: 대5 (위치·도착) + 대6-1 (FCM 기반) — 한성(레이더) 쪽과 가장 많이 맞춰야 함
4. **4주차**: 대6-2/6-3 (알림·미루기) → 대7 (기록·랭킹) → 대8

## 먼저 결정해야 할 것 (내일 시작 전)

- [ ] **도착 판정을 누가 하는가**: 클라(레이더 앱)가 100m 판정 후 서버에 보고 vs 서버가 위치로 직접 계산. 발표자료에서는 "자동 도착 판정"이라 클라 판정 + 서버 검증이 현실적.
- [ ] **Functions 호출 방식**: callable(HTTP) 중심으로 갈지, Firestore 트리거 중심으로 갈지. 지금 구조는 HTTP 함수로 시작.
- [ ] **Firebase 프로젝트 소유자**: 팀원이 같이 접근해야 하므로 IAM 권한 추가 필요.
- [ ] **카카오 REST API 키**: 서버 환경변수(Secret)로만 보관, 레포에 커밋 금지.
